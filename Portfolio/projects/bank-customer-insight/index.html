銀行零售客戶洞察平台

客戶分群與流失風險預測系統 — 從資料庫到商業智慧報表的端到端分析平台

本專案以銀行客戶流失預測（約 1 萬筆，資料取自 Kaggle）為基礎：零售銀行每年投入大量成本挽留客戶，但客戶經理往往不清楚「哪些客戶正在流失」以及「為什麼流失」。本專案建立一套端到端的資料分析平台，從資料庫層到商業智慧報表層，將原始客戶資料轉換為可執行的商業洞察，協助銀行識別高價值、高流失風險的客群並提出具體因應建議。

01

專案背景與目標

多數銀行的客戶關係管理停留在「事後補救」— 客戶解約後才進行客服回訪，錯失挽留的黃金時機。本專案的目標是建立一套主動式的風險識別系統，達成以下三個目的：

  • 將客戶依行為與資產特徵分群，找出真正需要優先關懷的客群
  • 建立流失預測模型，提早識別高風險客戶而非被動等待解約
  • 將分析結果轉換成客戶經理看得懂、用得上的儀表板，而非停留在資料科學家的筆記本裡
02

系統架構

採用三層式架構，將資料儲存、分析運算、視覺呈現明確分離，對應真實企業資料團隊的分工模式：

資料層　PostgreSQL儲存原始客戶資料與分析結果，以 SQL View 預先整合供下游查詢
→
分析層　Python讀取資料庫進行客戶分群與流失預測建模，結果寫回資料庫
→
呈現層　Power BI直接連接 PostgreSQL，產出互動式儀表板，不在報表端進行運算
資料流向：原始資料匯入 PostgreSQL → Python 讀取並執行分群 / 預測模型 → 結果寫回 PostgreSQL 結果表 → Power BI 連接資料庫產出視覺化報表
03

資料與分析方法

資料來源為銀行客戶資料集，涵蓋 10,000 筆客戶紀錄，欄位包含信用分數、地區、年齡、資產餘額、持有產品數、活躍狀態等 13 項特徵。

客戶分群

採用 K-means 演算法，依「資產規模、產品持有數、活躍度、年齡、薪資」五個特徵進行分群，並依各群平均特徵自動判斷命名，將技術結果轉換為具商業意義的客群描述，而非僅呈現群組編號。

流失預測

採用 Random Forest 分類模型，以信用分數、地區、性別、年齡、任職年資、資產餘額等 10 項特徵預測客戶流失機率，並輸出特徵重要性排序作為風險因素解釋。

核心發現

Insight Summary
  • 資產規模不是流失的關鍵因素 — 「高資產低互動型」流失率 (29%) 是「高資產活躍型」(13%) 的兩倍以上，顯示互動頻率比資產規模更能預測流失風險
  • 「高資產低互動型」客群規模最大（3,251 人、平均資產超過 10 萬），同時流失率偏高，是銀行應優先投入關懷資源的客群
  • 「年輕活躍型」流失率最高 (36%)，值得進一步拆解其流失原因，可能與產品適配度或費用結構有關
  • 年齡 × 薪資散佈圖進一步驗證：流失客戶（紅點）明顯集中在 45~60 歲區間，與 SHAP 分析結果（年齡為最重要風險因子）相互印證

05

進階機器學習：模型比較與可解釋性分析

為了讓模型選擇有嚴謹的依據，而非僅憑單一演算法的結果，進一步比較了 4 種分類演算法，並對表現最好的候選模型進行超參數調校，最後用 SHAP（SHapley Additive exPlanations）取代原本簡化的全域特徵重要性，做到「逐客戶」層級的個人化風險解釋。

四個模型的原理與差異

模型核心邏輯優點限制
Logistic Regression 假設每個特徵對「流失與否」的影響是線性、可加總的，用一條超平面分割留存／流失客戶 簡單、可解釋性最直接（係數就是影響力） 抓不到特徵之間的交互作用（例如「年齡大＋產品少」的組合效應），也抓不到非線性關係
Decision Tree 用一連串「if-else」規則切分資料（例如先看年齡>40，再看產品數<2） 能抓非線性關係、規則好懂 單一棵樹容易過度擬合（記住訓練資料的雜訊），穩定度差（CV std 0.008，數字上看起來低，但單棵樹本質風險高）
Random Forest 同時長出幾百棵決策樹，每棵樹只看部分資料跟部分特徵，最後投票平均 大幅降低單棵樹的過擬合風險，穩定性好 樹與樹之間策略有點「隨機」，調校空間相對平緩
XGBoost 也是很多棵樹，但不是同時獨立長，而是一棵接一棵，每棵樹去修正前一棵的錯誤（梯度提升） 通常精準度最高，尤其在表格型資料 對超參數比較敏感，沒調好反而容易 overfit

這解釋了本次結果的排名邏輯：LR (0.768) < DT (0.826) < RF (0.859) ≈ XGB (0.861)。LR 輸在「線性假設」太簡化，無法捕捉像「高資產＋低互動」這種交互作用；樹狀模型都能抓到，而集成方法（RF、XGB）又比單棵樹穩。

Discussion Point

這是一個很好的討論點：不是所有模型調校都有感。Random Forest 本身結構自帶「隨機取樣＋平均」的正則化效果，預設參數通常就已經接近最佳，調校空間有限；而 XGBoost 對 learning_rate（學習率）、max_depth 這些參數敏感度高，原本預設值可能學太快或樹太深，調成 learning_rate=0.03（放慢學習）＋ max_depth=5（限制樹深防止過擬合）之後，才把潛力發揮出來。

SHAP 分析結果與先前用年齡、薪資散佈圖觀察到的現象一致 — 年齡是最主要的流失驅動因子。相較於傳統的全域特徵重要性（所有客戶共用同一組排名），SHAP 能為每一位客戶計算專屬的風險因素組合，例如同樣是高流失機率，A 客戶可能是「年齡（提高風險）＋產品數過少（提高風險）」，B 客戶則可能是「活躍度低（提高風險）＋資產規模大（降低風險）」。這種顆粒度的解釋更貼近客戶經理實際想知道的「這一位客戶，我該怎麼做」，而不只是「哪個變數整體上重要」。

06

商業建議

  • 針對「高資產低互動型」客群，建議由客戶經理主動關懷聯繫，而非等待流失後才回訪
  • 針對「年輕活躍型」客群，建議進一步分析其產品使用行為，評估是否需調整產品組合或定價策略
  • 將流失預測模型產出的高風險名單，整合進客戶經理的日常工作清單，建立「預測 → 行動」的閉環流程
